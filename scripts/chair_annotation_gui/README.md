# チェアログ・連続アノテーションGUI

原ログを参照しながら、ブランクを含む連続した臨床行為を人が記録するローカルアプリです。処置名は日本語、器具名は `instruments.json` の英語40種類で保存します。モデルの学習・推論は実行しません。

## Windows・macOSへ移す（配布版1.1）

`PORTABLE_GUIDE.html` をブラウザで開くと、移行手順を読めます。

元のGUIの「別PCへ移す ZIP」から、アプリ・選択症例の原ログ・注釈の全保存履歴をまとめます。「全保存症例をまとめる」を選ぶと、全保存症例を対象にします。ZIPは内容とSHA256を照合してから完成ファイルとして保存します。未完了の下書きも移行できます。動画は別にコピーし、移行先で選び直してください。

ZIP全体を展開し、Windowsでは `START_WINDOWS.bat`、macOSでは `START_MAC.command` を開きます。別PCにもPython 3.10以上が必要です。新規インストールは [Python公式サイト](https://www.python.org/downloads/) の現在の通常版を使用してください。Pythonを同梱したexe/appではありません。追加のpip/npmインストールやGPUは不要です。

同梱データがあれば自動で使用し、アプリだけの配布版ではデータフォルダを選択します。ブラウザは自動で開き、空いているlocalhostのポートを使用します。起動時の端末は編集が終わるまで開いておきます。フォルダ設定はアプリ内の `launcher_config.json` に保存し、配布ZIPには含めません。

別のフォルダを選ぶには `python3 launcher.py --choose-folder`（Windowsは `py -3 launcher.py --choose-folder`）。フォルダ選択画面が使えない環境では、端末でパスを入力できます。

保存済み注釈の自動同期・複数PC間の競合統合はありません。作業を移すときに新しい移行ZIPを作り、既存フォルダに上書きせず別フォルダへ展開してください。移行後の保存先は `ChairLogAnnotator/C31/Output/chair_continuous_annotations_v1` です。原ログ・確認根拠・境界の誤差・履歴を保持します。

Windows/macOS実機での起動確認は未実施です。Linuxで移行ZIP作成・別パスへの復元・再編集・出力をテストし、日本語読込はUTF-8を明示しています。

アプリだけの配布ZIPを作成する場合:

```bash
python3 scripts/chair_annotation_gui/portable.py --output /path/to/new/ChairLogAnnotator_Windows_macOS.zip
```

## 起動

Python 3.10以降と、現行のChromeまたはFirefoxを使用します。Python標準ライブラリだけで動作し、pip/npmのインストールや外部CDNは不要です。

`chair-activity` が `C31` 内にある配置では、次のコマンドで起動できます。

```bash
python3 scripts/chair_annotation_gui/server.py
```

別の配置の場合は、実際のデータルートを指定します。

```bash
python3 scripts/chair_annotation_gui/server.py --root /path/to/C31 --port 8765
```

ブラウザで **http://127.0.0.1:8765** を開きます。停止は端末で `Ctrl+C`。`start.sh` から起動しても構いません。

入力は `C31/chair_export/<date>/<chair>/Chair_log_seq_<number>.dat`。既存の `C31/ChairLog_annotations1438_1479.csv` がある場合は参照欄に表示します。CSVの原ログSHA256が一致しない注釈や範囲外の注釈は参照エラーとして明示し、出力の監査情報に記録します。

既定の保存先は `C31/Output/chair_continuous_annotations_v1`。別の新規フォルダには `--output /path/to/C31/Output/new_annotation_project` を指定します。原ログ、既存注釈、既存解析結果は変更しません。同じ保存先を共有するサーバープロセスは1つだけ起動してください。

## 操作

1. 症例を検索し、記入者、症例の用途、対象範囲を確認します。既定では原ログの全時間を対象とし、範囲外を除いた場合は出力にその時間を記録します。
2. 原観測グラフ上をドラッグして区間を指定します。開始・終了の秒数を直接入力することもできます。
3. 臨床行為、処置名、器具、ログの観測状況、確認根拠、臨床内容の確実性、境界の誤差を入力します。
4. 「この区間の記入内容を確認した」をチェックし、「区間を反映して保存」。確認後に内容を編集するとチェックは外れます。
5. 未記入部分は個別に記録するか、「未記入を『不明』に」で下書きを作成します。自動生成された不明区間は未確認です。各区間を確認してください。
6. 品質チェックを見て、未記入・重複・未確認を解決してから「最終出力 ZIP」を押します。途中の状態は「下書き出力」で保存できます。

表の行または注釈帯をクリックすると区間を編集できます。「指定時刻で分割」は、タイムラインで指定した時刻を使います。分割後は確認をやり直します。「元に戻す」は現在開いている症例の直近30回までの区間操作に対応します。削除・修正前の保存履歴はディスクに残ります。

`Ctrl+S` は編集中の区間も反映して保存、`N` は新しい区間、`[` / `]` は指定時刻を開始/終了へ反映します。記入者・症例用途・動画設定は変更時に保存します。区間フォームへの入力だけではディスク保存されません。「区間を反映して保存」または `Ctrl+S` を使用してください。

## 記録上の区別

- 臨床行為: `treatment`（処置名あり）、`procedure_unspecified`（処置あり・内容不明）、`no_procedure`（確認された処置なし）、`unknown`（不明）。
- 器具: `known`（選択した器具）、`none`（器具なしを確認）、`unknown`（不明）。空の器具配列だけから器具なしと解釈しません。
- 複数器具: `simultaneous`、`sequential`、`uncertain` を区別。区間内に登場した器具の一覧であり、全区間を通じた同時稼働を意味しません。
- ログ観測状況: 臨床行為とは別の項目。イベントのない時間を自動的に処置なし・器具なしと判定しません。
- 根拠: 動画、直接観察、診療記録、ログからの推測、既存注釈、不明を区別。ログの推測・旧注釈だけを独立した臨床正解に昇格しません。
- 時刻: 原ログ先頭を0秒とする相対時刻。日時は原ログのAsia/Tokyoとして保存します。区間は `[start_s, end_s)`。5秒刻みへの丸めは行いません。
- 境界誤差: 開始・終了それぞれの±秒。空欄は `null`（不明）であり0ではありません。境界が明確な場合のみ両方0にします。

器具の `articulatin_paper_holder` を含む綴りは、指定されたリストをそのまま保存しています。`3way_syringe` と `syringe` は別項目です。旧注釈の「5倍速」「ストレート」などは曖昧な対応付けを避けるため自動変換しません。人が英語の器具を選び、倍率などの詳細はメモに残してください。旧注釈を追加した区間には元ID・元ファイルSHA256を残します。

現在の時間区分は、重複のない主処置の1レーンです。同時に複数の独立した処置を記録する専用の複数レーン機能はありません。複数器具は選択可能です。複合処置を1区間に記録する場合は日本語の処置名・メモに明示してください。

## 原ログ・動画の表示

全イベント数と対象コードのイベント数を別の帯で表示し、3つの信号コードを選択できます。対象コードは `20039, 20011, 20101, 20742, 20743, 20108, 20774, 20776, 10014, 10015, 90012`。他のコードも信号選択に表示します。

数値は原観測の点として表示し、欠測のゼロ埋めや補間をしません。状態を点で表示するため、記録間の状態継続を描いた階段線ではありません。画面の空白だけで状態が不明になった・OFFになったと判断しないでください。表示範囲の1信号が4,000点を超える場合は表示だけを間引き、元の件数と表示数を明示します。範囲を拡大して詳細を確認できます。全イベントの帯は表示用の集計であり、物理信号のゼロを表しません。

動画はブラウザのファイル選択から開きます。動画の0秒に対応するログ時刻を設定し、動画時刻を区間の開始・終了へ反映できます。同期は固定オフセットです。長い動画で時計のずれがある場合、別途確認が必要です。動画ファイルはブラウザ内で再生し、アプリのサーバーにはアップロードしません。保存するのはファイル名とオフセットです。ブラウザ再起動後は同じファイルを選び直してください。

## 保存とexport

ディスク保存は症例ごとの `latest.json` と不変の `revision_*.json`。同じ症例を別タブで更新した場合は古いリビジョンでの上書きを拒否します。競合時は下書き出力でブラウザのJSONを退避してから再読込してください。ブラウザにも反映済みの下書きを保持しますが、ディスク保存を主とします。

症例ごとのZIPには以下を含みます。

- `annotations.json`: 全項目を保持した再編集用データ。
- `intervals.csv`: UTF-8 BOM付きの解析・表計算用データ。器具と根拠の配列はJSON文字列。
- `quality.json`: 未記入、重複、未確認、警告。
- `manifest.json`: 原ログSHA256、日時、対象範囲、範囲外、無効時刻行番号、件数、版、出力状態。
- `instruments.json`, `checksums.json`, `README.txt`。

「全保存症例をまとめる」を選択すると、全保存症例の個別ファイルに加えて `all_intervals.csv` と `collection_manifest.json` を出力します。未保存症例は対象外であることと、利用可能な原ログ件数・要求した保存症例件数・実出力件数を記録します。一括最終出力で未完了症例があれば、対象IDと理由を示して中止します。未完了症例を黙って除外しません。

最終出力は、全区間に編集確認があり、未記入・重複がなく、記入者があることを要求します。内容が不明な区間も、確認したうえで `unknown` として最終出力できます。`final` は編集が完了したことを示し、すべての臨床内容が確定したことを意味しません。`no_procedure`、および確認済みの臨床行為にはログ以外の根拠と説明が必要です。

`clinical_ground_truth_eligible` / `instrument_ground_truth_eligible` は確認・根拠・既知ラベルに基づく補助フラグです。境界の妥当性や診療記録の時間精度を保証しません。長い区間の器具ラベルをすべての短窓へ無条件に引き継がないでください。

JSON再読込は対応する症例を開き、ZIP内の `annotations.json` を選択します。原ログSHA256・症例ID・時間範囲・英語器具名を検証します。CSVは閲覧・解析向けであり、CSVの再インポート機能はありません。CSVで式として解釈される文字列は先頭にアポストロフィを付けます。原文はJSONに保持します。

## テスト

```bash
python3 -m unittest discover -s scripts/chair_annotation_gui/tests -p 'test_*.py' -v
node --check scripts/chair_annotation_gui/static/app.js
```

Chromeの実ブラウザテストは、Node 22以降とローカルのChromeを使用します。実症例の注釈は変更しません。

```bash
python3 scripts/chair_annotation_gui/tests/run_fixture.py --root /tmp/chair-annotation-test --port 8766
# 別の端末
google-chrome --headless=new --remote-debugging-port=9225 --user-data-dir=/tmp/chair-annotation-test-chrome --no-first-run about:blank
# 別の端末。出力先は毎回新しいフォルダを指定します。
node scripts/chair_annotation_gui/tests/test_browser.mjs http://127.0.0.1:8766 /tmp/chair-annotation-test-results
```

GitHubにはアプリ・テスト・説明のみを公開し、原ログ、注釈JSON/CSV、症例画像、動画、通知先を含めません。アプリは127.0.0.1だけで待ち受け、外部ネットワークへの公開機能はありません。
